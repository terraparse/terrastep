# terrastep

terrastep checks planning documents against a frontmatter-and-body format. Full spec: `references/format.md`. Full verb/config reference: `references/verbs.md`.

## First: does terrastep even apply here?

Before treating any rule below as binding, check that it applies to the file you're about to
write or edit:

1. Does this repository have a `terrastep.toml` at its root (or does `terrastep` run without
   error, meaning it found one, or is running on defaults)?
2. Is the file under one of `scan_dirs` (recursively)? Run `terrastep survey` or read
   `terrastep.toml`'s `scan_dirs` if unsure.

If either answer is no, the format does not apply to this file — write it however the task needs,
and stop reading here. This skill only governs documents that terrastep itself would scan.

## Writing a new `type: design` document

1. `terrastep next-id` for the number.
2. Scaffold: frontmatter (`status: planning`, today's `status_changed`, `type: design`, `next`),
   at least a `summary` or `motivation` section, then exactly `## Blockers`, `## Questions`,
   `## Recommendations`, `## Sequencing` in that order. See `references/format.md` for the full
   shape (item tags, recommendation coverage, role headings).
3. `terrastep check`. On any failure, look up the code in `references/format.md` and fix it —
   don't guess twice at the same rule.
4. `terrastep build` to regenerate the index.
5. Re-run `terrastep check` before finishing the turn. Closing this loop here is what makes the
   pre-commit and Stop hooks (already installed if this repo ran `terrastep install-hooks`)
   uneventful rather than a surprise later.

## Fixing a document that fails `terrastep check`

Read the failure code from the output, find it in `references/format.md`, apply the fix, re-run
`terrastep check`. Never guess at a fix without reading what the code actually means — the codes
are specific (e.g. `body-r-cover` means a Recommendations section is missing an item's id, not
that recommendations are missing entirely).

## Bringing existing undocumented markdown under the format

```
terrastep migrate propose     # writes a proposal table; touches nothing else
# review the table by hand — it is only a guess, and flags weak ones
terrastep migrate apply       # prepends the reviewed frontmatter
terrastep build && terrastep check
```

## Setting terrastep up in a repository for the first time

Write a `terrastep.toml` naming `scan_dirs`, run `migrate propose`/`apply` on what's already
there, then `terrastep install-hooks`. See `references/verbs.md` for every verb and flag.
